# 改寫示例

所有示例都是自造的。每個示例後面標出用到的規則編號。

## 1. 概念解釋

**改寫前**

> 值得注意的是，雜湊表之所以能夠實現平均意義上常數時間的查詢，在很大程度上是因為它通過雜湊函式將鍵對映到陣列中的某個位置，不過當多個鍵被對映到同一位置的時候，就會產生所謂的衝突，而衝突的處理方式會對效能產生不小的影響。

**改寫後**

> 雜湊表查詢一個鍵，平均只需要常數時間。原因是：雜湊函式把每個鍵算成一個數組下標，程式直接去這個下標取值。
>
> 兩個不同的鍵可能算出同一個下標。這種情況叫「衝突」。雜湊表處理衝突的方法，對效能影響很大。

用到：13（刪「值得注意的是」）、5（拆句）、6（寫清主語）、1（給「衝突」下定義）、14（保留「平均」「很大」）。

## 2. 操作步驟

**改寫前**

> 在開始之前，您需要先確保已經安裝了 Node.js，之後可以通過在終端中執行 npm install 來進行依賴的安裝，安裝完成以後再執行 npm run dev，如果埠被佔用的話可以在 .env 檔案裡面修改 PORT。

**改寫後**

> 前提：本機已安裝 Node.js。
>
> 1. 在終端執行 `npm install`，安裝依賴。
> 2. 執行 `npm run dev`。
> 3. 如果提示埠被佔用，開啟 `.env` 檔案，修改 `PORT` 的值。

用到：9（編號、動詞開頭、不寫「您」）、3（「進行依賴的安裝」→「安裝依賴」）、8（條件放前面）、15（命令原樣保留）。

**改寫前**

**改寫後**

> 我改了 2 個檔案：
>
> - `auth/session.ts`：令牌過期時，先重新整理令牌，再重試請求。之前直接報錯。
> - `auth/login.ts`：密碼為空時，前端直接提示，不再發請求。
>
> 我跑了現有的登入測試，全部通過。我沒有測這兩種情況，需要你確認：
>
> - 重新整理令牌也過期時，使用者是否被帶回登入頁。
> - 網路斷開時，重試會不會無限迴圈。

用到：2（「全面梳理」「必要的調整」換成具體動作）、12（並列內容用列表）、14（保留「需要驗證」這個限定，並寫清驗證什麼）。
